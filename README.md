# CV & Resume Intelligence Engine

An AI-powered CV information extraction app that turns an uploaded PDF
resume into a clearer, structured candidate profile. Built with
**Streamlit**, **PyPDF**, and the **Qwen2.5-1.5B-Instruct** language
model from Hugging Face Transformers, with **Ngrok** used to expose the
Streamlit app through a temporary public tunnel for demos.

> **Important:** This project extracts and organizes information already
> present in a CV. It does not guarantee that a CV will pass an
> Applicant Tracking System (ATS), rank candidates, verify the truth of
> claims, or measure a person's actual ability.

## Why this project?

A candidate's skills and experience can be difficult to review when
information is scattered across a resume. This project explores how a
language model can help make that information easier to inspect by
extracting key details into a readable profile.

## Features

-   Upload a CV in **PDF** format through a Streamlit interface.
-   Extract text from PDF pages using **PyPDF**.
-   Preview the extracted raw text before processing.
-   Use **Qwen2.5-1.5B-Instruct** to organize information into a
    structured Markdown profile.
-   Extract key fields such as:
    -   Full name
    -   Contact details
    -   Technical skills
    -   Work experience
    -   Education
-   Cache the model in Streamlit so it does not need to be reloaded on
    every interaction.
-   Run the Streamlit app through an **Ngrok** tunnel for remote
    demonstrations.

## How it works

1.  **Upload:** The user uploads a PDF resume in the Streamlit
    interface.
2.  **Text extraction:** PyPDF reads the document and collects
    extractable text from its pages.
3.  **Prompt construction:** The extracted text is passed to the
    language model with instructions to identify and organize key
    candidate details.
4.  **LLM inference:** Qwen generates a Markdown-formatted candidate
    profile.
5.  **Display:** The app displays the generated profile in the
    dashboard.

## Requirements

-   Python 3.10+ recommended
-   A CUDA-compatible NVIDIA GPU and a working CUDA/PyTorch setup are
    recommended for the current implementation.
-   Internet access on the first run to download the model from Hugging
    Face.
-   An Ngrok account and authentication token if you want to expose the
    app through an Ngrok tunnel.

**Hardware note:** The current code loads the model using
`torch.float16` and `device_map="auto"`, and sends inference inputs to
`"cuda"`. It therefore assumes CUDA is available. CPU-only execution is
not supported by the current notebook code without modifications. Model
loading and inference may require substantial GPU memory.

## Installation

### 1. Clone the repository

``` bash
git clone <YOUR_GITHUB_REPOSITORY_URL>
cd <YOUR_REPOSITORY_NAME>
```

Replace the placeholders with your repository URL and folder name.

### 2. Create and activate a virtual environment

**Windows (PowerShell):**

``` powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

**macOS / Linux:**

``` bash
python -m venv .venv
source .venv/bin/activate
```

### 3. Install dependencies

``` bash
pip install streamlit pyngrok torch transformers pypdf
```

Install the PyTorch build that matches your CUDA environment by
following the official PyTorch installation instructions if the default
installation does not support your GPU.

### 4. Configure Ngrok (optional)

For local-only use, you do not need Ngrok. To use a public demo tunnel,
set your Ngrok authentication token as an environment variable rather
than placing it directly in source code.

**Windows PowerShell:**

``` powershell
$env:NGROK_AUTHTOKEN="YOUR_NGROK_AUTHTOKEN"
```

**macOS / Linux:**

``` bash
export NGROK_AUTHTOKEN="YOUR_NGROK_AUTHTOKEN"
```

Your application or launch script should read the token from the
environment, for example:

``` python
import os
from pyngrok import ngrok

token = os.environ.get("NGROK_AUTHTOKEN")
if token:
    ngrok.set_auth_token(token)
```

The notebook version currently includes an authentication token directly
in a code cell. **Do not publish that token. Revoke/rotate it in your
Ngrok dashboard before pushing the notebook to GitHub**, and remove it
from the notebook and any Git history where possible. Environment
variables and a `.env` file excluded by `.gitignore` are safer than
hardcoding secrets.

## Run the app locally

If `app.py` is present:

``` bash
streamlit run app.py
```

Then open the local URL printed by Streamlit, usually:

``` text
http://localhost:8501
```

The first run downloads the model and may take time. Subsequent runs can
use the local Hugging Face cache.

## Run with Ngrok

After configuring your Ngrok token, start Streamlit in one terminal:

``` bash
streamlit run app.py --server.port 8501
```

Then, in a second Python session or a small launch script, create a
tunnel:

``` python
import os
from pyngrok import ngrok

ngrok.set_auth_token(os.environ["NGROK_AUTHTOKEN"])
public_url = ngrok.connect(8501)
print("Public demo URL:", public_url)
```

Keep the process running while you use the public URL. The URL is
temporary and should not be treated as a permanent deployment. Avoid
uploading real or sensitive CVs to a publicly accessible demo.

## Example output

The model is prompted to produce a readable profile with sections
similar to:

``` markdown
## Full Name
Candidate name, if available in the CV

## Contact Details
Email address, phone number, or other contact information found in the document

## Technical Skills
Skills explicitly mentioned in the CV

## Work Experience
Roles, organizations, dates, and responsibilities when available

## Education
Degrees, institutions, and dates when available
```

The exact output depends on the content and layout of the uploaded CV
and the model's response.

## Limitations

-   **PDF text extraction:** Scanned or image-only PDFs may produce
    little or no text because the current implementation does not
    include OCR.
-   **Extraction accuracy:** The language model can omit details,
    misinterpret text, or generate unsupported information. Always
    review the output against the original CV.
-   **Formatting:** Complex columns, tables, icons, and unusual layouts
    may not extract in the intended reading order.
-   **ATS compatibility:** The app does not parse a specific ATS's rules
    or guarantee that a resume will pass automated screening.
-   **Candidate evaluation:** It does not score candidates, compare
    applicants, validate credentials, or infer a person's true
    competence.
-   **Privacy:** CVs contain personal data. Use test or consented
    documents, restrict access to public demos, and avoid uploading
    sensitive resumes to a shared tunnel.
-   **CUDA dependency:** The current inference code expects a CUDA
    device; CPU fallback has not been implemented.
-   **Ngrok exposure:** Anyone with access to the active public URL may
    be able to reach the app, depending on the tunnel and app
    configuration. Do not use an unrestricted public tunnel for
    confidential CVs.

## Responsible use

This tool is intended to assist with **information extraction and
organization**, not to make hiring decisions. Review extracted details
manually, give candidates a fair opportunity to represent their
experience, and do not use the generated profile as the sole basis for
employment decisions.
